Each row's render count is incremented by its own effect. Append and pop leave the whole prefix untouched — watch every existing row hold its count at 1 while only the new/edited row ticks. The pool alloc (last op) chip reads lite-signal's stats(): append reuses a parked scope from a prior pop (zero alloc once warm), so a long push/pop cycle never grows the pool. A non-tail edit (prepend, reorder) would fall through to the general keyed diff — still correct, just not the fast path.
